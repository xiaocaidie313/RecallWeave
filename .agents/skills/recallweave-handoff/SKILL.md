## 恢复项目上下文

用当前对话中的项目名、组件名和具体问题定位要查的历史。先调用 RecallWeave 的 `search_memories`，工具名可能带客户端的服务器前缀。优先采用包含项目和事项的关键词，同名项目的记录须核对归属。默认查有效记忆，追溯已停用的旧方案时才带 `include_inactive`。

首查未找到相关原文时，最多用一组不同关键词补查一次。仍无依据就报告查找范围和缺口。用户要求全面审计，或新命中给出了明确的补查线索时，可以继续。

用 `get_messages` 读取相关命中项的 `session_id` 和消息范围（每次至多 50 条）。合并相邻或重叠的范围，复用已经读过的原文。摘要用于定位，决定、理由和变更需要原文支持。遇到“可以”“就这个”之类的简短确认，连同前面的提案一起读取。

交接时按问题给出当前决定、变更原因和仍待处理的事项，逐项附上能核对的会话 ID 和消息范围。明确区分用户确认、助手建议和已完成的工作。保留被替代的方案；跨会话只能依据原文日期或明确的替换关系判断先后。冲突无法消解时列出两处证据并标为待确认。只找到摘要或未找到依据时说明已核对到哪里，保留缺口。

## 保存交接原文

当前用户明确要求保存指定内容时，才调用 `import_transcript`。提交实际来源 `source_tag`、简短的 `name` 和按原顺序排列的 `messages`（每项为 `role` 和 `content`）。保留可见的原文和发言角色，不补写看不到的内容，也不把新生成的交接摘要当作原话。

持续保存同一段对话时复用相同的 `external_session_id`，使用客户端可用的稳定会话 ID。若由你创建标识，首次保存后保留它供后续使用。按保存片段的连续顺序编号，`seq_start` 默认从 1 开始。既可重发完整前缀，也可从下一个序号提交新消息，每次至多 50 条。已保存部分必须逐字一致。消息发生编辑或分叉时使用新的外部会话 ID。

返回 `session_id`、总条数 `message_count`、本次新增条数 `added_messages` 和 `extract_status`。提炼失败或跳过时，说明原文已保存、可凭 ID 读回，检索记忆尚未就绪。带外部会话 ID 的同一批原文可以安全重试，以恢复未完成的提炼。未提供外部会话 ID 时每次都会新建会话，结果不明确时先报告状态未知。只读 MCP 或工具未连接时说明限制，保持当前任务的其他工作照常进行。
